# Story 7.3 — API `POST /api/waitlist` + DB schema CRM-light + honeypot + rate limit

**Status:** Ready for Review
**Epic:** 7 — Landing & Waitlist
**Tipo:** Backend + DB
**Estimativa:** 1.5d
**Depends on:** — (foundation)

## Contexto

Backend pra suportar o form da landing (story 7.2). Schema **CRM-light**
desde V1 — não é fila silenciosa, é base de dados de leads etiquetados
que vai ser consumida pelo Admin Panel (Epic 9).

Endpoint público (sem auth) protegido por **honeypot + rate limit**
(sem captcha — decisão fechada PRD 7).

## Acceptance Criteria

1. Migration drizzle cria types + tabela `waitlist`:
   - Types: `waitlist_status` enum, `waitlist_role` enum
   - Table com todos os campos definidos no PRD (id, email UNIQUE, name, bambu_count, role, state, city, telegram_handle, phone, status, tags array, notes, contacted_at, last_contact_at, source_utm jsonb, referrer, user_agent, ip_address, created_at, updated_at)
   - Indexes: `created_at`, `(status, created_at)`, `state` partial, `tags` GIN, `(ip_address, created_at)` (pra rate limit)
2. Endpoint `POST /api/waitlist` em `apps/api`:
   - Aceita JSON body com schema Zod compatível
   - Valida server-side todos os campos
   - **Honeypot:** se `website` field vier preenchido → retorna 200 OK silencioso (não insere, não loga)
   - **Rate limit:** max 3 cadastros / IP / hora → 429 se exceder
   - **UNIQUE email:** retorna 409 amigável "Você já está na lista, vamos te chamar em breve"
   - Captura automaticamente: `ip_address` (X-Forwarded-For ou socket), `user_agent` (header), `referrer` (header)
   - INSERT com status `'new'` default
3. Endpoint público — não requer auth (waitlist é pra visitor)
4. CORS aberto pra `guiaprint3d.com` e localhost dev
5. Logs estruturados (sem PII no log — só ip + status + duration)
6. Sanitização: trim em todos os strings, lowercase no email, sem HTML
7. Erro 4xx/5xx retorna `{ error: { code, message } }` formato consistente

## Dev notes

- **Rate limit storage:** consultar `waitlist` table mesmo
  (`SELECT count(*) FROM waitlist WHERE ip_address = $1 AND created_at > NOW() - INTERVAL '1 hour'`).
  Sem Redis V1 — Postgres aguenta
- **Honeypot behavior:** importante retornar 200 fake (não 4xx) pra bot
  não tentar de novo. Logar como `bot_detected` count pra métrica
- **IP detection:** ordem `X-Forwarded-For` (primeiro IP, EasyPanel
  está atrás de proxy) → `X-Real-IP` → `req.ip` (socket)
- **Email lowercase:** garante UNIQUE constraint funciona corretamente
- **UTM:** params chegam do client via body (form captura via
  useSearchParams). Backend só armazena
- **Schemas compartilhados:** `packages/shared/src/waitlist.ts` exporta
  `WaitlistSubmitSchema` Zod usado por client (story 7.2) e server (esta story)

## Schema reference (PRD 7 final)

```sql
CREATE TYPE waitlist_status AS ENUM ('new', 'contacted', 'engaged', 'invited', 'converted', 'lost');
CREATE TYPE waitlist_role AS ENUM ('hobbyist', 'small_shop', 'studio', 'business', 'other');

CREATE TABLE waitlist (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email text NOT NULL UNIQUE,
  name text NOT NULL,
  bambu_count integer NOT NULL CHECK (bambu_count >= 0),
  role waitlist_role NOT NULL DEFAULT 'other',
  state text,
  city text,
  telegram_handle text,
  phone text,
  status waitlist_status NOT NULL DEFAULT 'new',
  tags text[] DEFAULT '{}' NOT NULL,
  notes text,
  contacted_at timestamp with time zone,
  last_contact_at timestamp with time zone,
  source_utm jsonb,
  referrer text,
  user_agent text,
  ip_address inet,
  created_at timestamp with time zone DEFAULT now() NOT NULL,
  updated_at timestamp with time zone DEFAULT now() NOT NULL
);

CREATE INDEX waitlist_created_at_idx ON waitlist (created_at DESC);
CREATE INDEX waitlist_status_idx ON waitlist (status, created_at DESC);
CREATE INDEX waitlist_state_idx ON waitlist (state) WHERE state IS NOT NULL;
CREATE INDEX waitlist_tags_idx ON waitlist USING gin (tags);
CREATE INDEX waitlist_ip_recent_idx ON waitlist (ip_address, created_at DESC);
```
