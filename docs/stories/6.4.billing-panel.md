# Story 6.4 — Painel de cobrança (fatura atual, próximas, métodos pagamento)

**Status:** Ready
**Epic:** 6 — Pagamentos & Monetização
**Tipo:** Frontend
**Estimativa:** 2d
**Depends on:** 6.3 (subscription ativa), 6.6 (webhooks alimentam invoices)

## Contexto

Owner do tenant precisa ver histórico de cobrança, baixar
comprovantes, gerenciar método de pagamento.

## Acceptance Criteria

1. Página `/settings/billing/history` (ou aba em `/settings/billing`):
   - **Lista de invoices** (`subscription_invoices`):
     - Data, valor, status (badge), método pagamento, link
       Asaas-hosted pra ver fatura completa, link NF-e (V1.1)
   - Paginada (12/page)
   - Filtro por status (paid/pending/failed/refunded)
2. **Próxima fatura** (card destaque no topo):
   - Data prevista (de `subscription.current_period_end`)
   - Valor (do plan + cycle)
   - "Pagamento via {método salvo no Asaas}"
3. **Métodos de pagamento:**
   - Lista cartões salvos no Asaas (via API)
   - Botão `[Atualizar forma de pagamento]` → redirect pra Asaas
     hosted UI
4. **Dados de cobrança editáveis:**
   - Botão "Editar dados" → modal com tax_id_type, tax_id,
     billing_address
   - Submit re-sync com Asaas (call `updateCustomer`)
5. UI Mission Control style: tabela com `data-mc-card`,
   PageHeader `id="BILLING-HIST"`
6. Erro graceful se Asaas API down (mostra cache local)

## Dev notes

- **Cache invoices:** 5min server-side. Re-fetch ao trocar de página
- **Asaas hosted invoice:** cada invoice tem `invoiceUrl` na API.
  Linka direto (Asaas hospeda PDF)
- **NF-e link (V1.1):** se `subscription_invoices.nfe_pdf_url` existe,
  mostra botão `[Baixar NF-e]`. Senão "NF em emissão"
- **Edição billing info:** crítico re-sync com Asaas (Asaas precisa
  dos dados pra emitir cobranças e NF)
