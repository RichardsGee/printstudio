# Story 7.2 — Landing Page (hero + features + form + footer + demo video)

**Status:** Ready
**Epic:** 7 — Landing & Waitlist
**Tipo:** Frontend
**Estimativa:** 2-3d
**Depends on:** 7.1 (setup), 7.3 (API waitlist), 7.4 (privacy/terms), 7.5 (success page)

## Contexto

Landing pública em `guiaprint3d.com` comunicando o valor do PrintStudio
e capturando leads qualificados via form de waitlist rico. Visual
**Mission Control** consistente com o app autenticado.

## Acceptance Criteria

1. **HEADER sticky** com logo `// GUIAPRINT3D` + CTAs `[Entrar na lista]` `[Ver demo]`
2. **HERO** com:
   - Título: "Monitore suas Bambu Lab A1 de qualquer lugar"
   - Subtitle explicativo
   - CTA primário: `[Entrar na lista de espera]` (scroll pro form)
   - CTA secundário: `[▶ Ver demo (60s)]` → abre modal/iframe YouTube
   - Hero asset: GIF/WebP animado do kiosk (placeholder até asset real)
3. **FEATURES** grid 4 cards (mission cards estilo data-mc-card):
   - Monitor visual estilo Mission Control
   - Multi-impressora com reordenação drag-and-drop
   - Cloud nativo (sem bridge LAN)
   - Histórico + alertas em tempo real
4. **WAITLIST FORM** completo com qualificação:
   - Nome* (text, min 2 chars)
   - Email* (email format, lowercase)
   - Estado (dropdown BR 27 UFs)
   - Cidade (text opcional)
   - Qual seu uso?* (dropdown role: hobbyist/small_shop/studio/business/other)
   - Quantas Bambu? (radio: 1 / 2-3 / 4-10 / 11+)
   - Telegram @handle (text opcional)
   - WhatsApp telefone (text opcional, formato BR)
   - Campo honeypot `website` (invisible — story 7.3)
   - Checkbox aceito termos*
   - Submit `[Solicitar acesso]`
5. **FOOTER** com links: Sobre / Política / Termos / Contato + `guiaprint3d.com © 2026`
6. **Responsivo mobile** (375px sem scroll horizontal — segue padrão Story 5.1)
7. **SEO básico:** meta description, og:image, og:title, twitter:card
8. **Form validation** client-side + server-side (HTML5 + Zod) com mensagens de erro inline
9. Submit chama `POST /api/waitlist` (story 7.3), redireciona pra success page (story 7.5) em caso de sucesso, mostra erro inline se 4xx
10. Modal video YouTube embed responsivo (16:9), close X visível

## Dev notes

- **Form submission:** server action ou client `fetch` POST pra
  `/api/waitlist` (decidir: se marketing site é puramente static,
  precisa endpoint público no `apps/api` ou no app web — alinhar com
  Architect na story 7.3)
- **UTM tracking:** capturar via `useSearchParams` e enviar no payload
  do form (`utm_source`, `utm_medium`, `utm_campaign`, `utm_content`,
  `utm_term`, `referrer`)
- **Validation:** Zod schema compartilhado entre client + server (definir
  em `packages/shared` ou copiar)
- **Asset GIF:** placeholder até asset real do kiosk (Richard providencia)
- **Demo video:** placeholder YouTube link até video real ser gravado
- **Accessibility:** form com labels, aria-required, aria-invalid em erros
