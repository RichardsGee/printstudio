# Story 6.6 — Webhooks tratados: pagamento_confirmado, cancelado, vencido

**Status:** Ready
**Epic:** 6 — Pagamentos & Monetização
**Tipo:** Backend
**Estimativa:** 1.5d
**Depends on:** 6.1 (Asaas client foundation), 6.2 (subscriptions schema)

## Contexto

Asaas envia webhooks pra eventos críticos. Handler precisa ser
**idempotente** e **rápido** (<2s p95).

Cobre: PAYMENT_CONFIRMED, PAYMENT_OVERDUE, SUBSCRIPTION_CANCELED,
CUSTOMER_CREATED, REFUND_REQUESTED.

## Acceptance Criteria

1. Endpoint `POST /api/asaas/webhook` em `apps/api`:
   - Valida assinatura HMAC do webhook header (`asaas-access-token`
     ou similar)
   - Idempotency: lookup `asaas_webhook_events` por `event_id` UNIQUE
   - Se já processado, retorna 200 OK sem re-processar
   - INSERT em `asaas_webhook_events` com payload completo
2. Handler async (process queue ou inline) por `event_type`:
   - **PAYMENT_CONFIRMED:**
     - Update `subscriptions.status = 'active'`
     - Set `first_paid_at = paid_at` (se primeira vez)
     - Set `refund_eligible_until = first_paid_at + 7d`
     - Update `organizations.plan = subscription.plan`
     - INSERT em `subscription_invoices` com status='paid'
     - Dispara emissão NF-e (story 6.9 — V1.1, V1 noop)
     - Invalida cache de plan-limits
   - **PAYMENT_OVERDUE:**
     - Update `subscriptions.status = 'past_due'`
     - Schedule grace period de 7d (job que checa)
     - Email/notify owner (V2 com Resend)
   - **SUBSCRIPTION_CANCELED:**
     - Update `subscriptions.status = 'cancelled'`
     - Set `cancel_at_period_end = true`
     - Continua serviço até `current_period_end`
   - **REFUND_REQUESTED/CONFIRMED:**
     - Update `subscriptions.status = 'refunded'`
     - Update `subscription_invoices.refunded_at = now()`
     - Downgrade `organizations.plan = 'free'` imediatamente
     - Trigger story 6.5 archive flow
3. Retorna 200 OK mesmo se erro interno (Asaas re-envia se 5xx)
4. Logs estruturados com event_id pra debug
5. Idempotência testada: replay do mesmo webhook 2x = sem efeito
   colateral

## Dev notes

- **HMAC validation:** Asaas docs definem header. Validar timing-safe
- **Idempotency strategy:** check `event_id` em `asaas_webhook_events`
  table → se exists, return 200 sem processar
- **Process inline V1:** sem queue dedicada (Redis/Bull) V1. Se
  performance virar issue, V2 com job runner
- **Eventos não-mapeados:** logar warning + INSERT mas sem processar
  (forward compat com futuros eventos Asaas)
- **Status transitions:** state machine válida (ex: `cancelled` →
  `active` só via novo subscription, não webhook direto)

## CodeRabbit Integration

- Foco: **idempotency CRÍTICO** (revenue duplication), HMAC validation,
  webhook replay attacks, race conditions
- Severity: CRITICAL = block (duplo cobrança = revenue leak)

## Quality Gates

- [ ] Webhook fake replay (curl) 2x → DB tem 1 invoice (não 2)
- [ ] PAYMENT_CONFIRMED → subscription active + plan ativo

- [ ] SUBSCRIPTION_CANCELED → cancelled + cancel_at_period_end
- [ ] HMAC inválida → 401
- [ ] event_id duplicado → 200 OK silent (sem re-process)
