### Decisões

- **TSX puro em vez de Markdown/MDX:** decisão pragmática. AC dizia
  "markdown estático" mas o ganho de MDX (sintaxe markdown nos docs)
  não compensa adicionar plugin `@next/mdx` + dependência de
  `react-markdown` num app com `output: 'export'` (precisa de
  transpilation extra). Conteúdo é editado por Richard direto no JSX
  com helpers (`<H2>`, `<P>`, `<UL>`) — UX de edição idêntica a
  markdown, sem custo de bundle.
- **Domínio `guiaprint3d.com` + e-mail `suporte@guiaprint3d.com`** já
  hardcoded — Richard registra no launch. Mudar é 1 find/replace.
- **Foro placeholder "cidade a ser definida no registro do MEI":**
  conforme PRD decisão MEI/Simples, definitivo só quando registrar.
- **Tipografia consistente:** usei tokens Mission Control já existentes
  (`text-heading`, `text-body`, `--mc-accent-soft`) — zero CSS novo,
  zero novos tokens.
