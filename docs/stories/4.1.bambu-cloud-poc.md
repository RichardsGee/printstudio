# Story 4.1 — Bambu Cloud POC

**Status:** Draft
**Epic:** 4 — Cloud-only mode (sem bridge LAN)
**Tipo:** POC / Spike (3 dias)
**Risco:** Alto (API não-oficial, sujeita a quebra)

## Contexto

O PrintStudio hoje só funciona com **bridge local na rede da impressora**
(MQTT/FTPS LAN). Pra rodar 100% no EasyPanel sem agente local, precisamos
falar com a impressora via **stack cloud da Bambu**:

- `api.bambulab.com` — login email+senha → JWT
- `us.mqtt.bambulab.com:8883` — broker MQTT relay
- Subscribe `device/{serial}/report` recebe a mesma telemetria do LAN

**A Bambu não tem API oficial.** Os endpoints são reverse-engineered pela
comunidade (`Doridian/OpenBambuAPI`, `greghesp/ha-bambulab` no Home
Assistant). Histórico mostra quebra de compatibilidade ~2x/ano.

Antes de investir 3-4 semanas na epic completa, validar com POC de 3 dias
se a integração funciona pra conta + impressoras do projeto.

## Acceptance Criteria

1. Script standalone `apps/bridge/scripts/cloud-poc.ts` que:
   - Lê `BAMBU_EMAIL` + `BAMBU_PASSWORD` do env
   - Faz `POST api.bambulab.com/v1/user-service/user/login`
   - Lista impressoras vinculadas via `GET .../user/bind`
   - Resolve `userId` via `GET .../my/preference`
   - Conecta `mqtts://us.mqtt.bambulab.com:8883` com username `u_{userId}` + password = JWT
   - Subscribe `device/{serial}/report` de cada impressora
   - Publica `pushall` pra forçar snapshot inicial
   - Loga telemetria estruturada por 30s
2. Roda sem modificar código existente do bridge
3. Documentação clara de como executar
4. **Critério de sucesso:** ver `nozzle_temp` real (não null) chegando pelo
   `device/.../report` no terminal — confirmando que stack cloud entrega
   os mesmos dados do LAN

## Gate de decisão

| Resultado do POC | Próximo passo |
|---|---|
| ✅ Telemetria chega completa | Aprovar Epic 4 (Bambu Cloud client production-ready) |
| ⚠️ Login OK, MQTT OK, mas telemetria parcial | Investigar `pushall` + tópicos alternativos antes de aprovar |
| ❌ Login bloqueado (CAPTCHA, 2FA forçado) | Abandonar Caminho B, ficar com bridge LAN (Caminho A) |
| ❌ MQTT rejeita auth | Abandonar; Bambu mudou protocolo |

## Execução

```bash
# Pré-requisito: impressora em modo Cloud (não LAN-only). Confere no LCD:
#   Settings → WLAN → Cloud printing = enabled

cd apps/bridge
BAMBU_EMAIL='seu@email.com' BAMBU_PASSWORD='sua-senha' \
  pnpm tsx scripts/cloud-poc.ts
```

Não commitar credenciais. Use shell history que não persiste ou
`pass`/`1Password CLI` pra injetar.

## Riscos identificados

| Risco | Mitigação |
|---|---|
| Bambu adiciona CAPTCHA no login | POC trata `loginType: 'verifyCode'` com erro claro |
| 2FA obrigatório | POC trata `loginType: 'tfa'` com erro claro — usuário tem que desativar |
| Rate limit no login | POC só faz 1 request |
| MQTT cloud não relay LAN-only | AC documenta pré-requisito: modo Cloud habilitado |
| TUTK câmera (P2P) complicado | Fora do escopo do POC. Câmera será Story separada na Epic 4 |
