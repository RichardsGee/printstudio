# Story 6.3 — UI upgrade plan (free → pro/business, mensal/anual + captura tax_id/endereço)

**Status:** Draft
**Epic:** 6 — Pagamentos & Monetização
**Tipo:** Frontend + API integração
**Estimativa:** 3d
**Depends on:** 6.1 (Asaas client), 6.2 (schema)

## Contexto

User flow pra fazer upgrade: ver comparação de planos, escolher
cycle (mensal/anual com 20% desc), fornecer dados fiscais (CPF/CNPJ +
endereço), redirect pro checkout Asaas, voltar ativado.

## Acceptance Criteria

1. Página `/settings/billing` mostra:
   - Plano atual (badge cyan + "FREE" / "PRO" / "BUSINESS")
   - Status subscription (badge: ACTIVE/PAST_DUE/CANCELLED/EXPIRED)
   - Próxima cobrança (data + valor) se paid
   - Refund eligible until (se aplicável, story 6.8)
   - Botão `[Fazer upgrade]` (free) ou `[Mudar plano]` (paid)
2. **Tela de comparação de planos** (3 cards Mission Control style):
   - Free / Pro / Business com limits visuais
   - Toggle **[Mensal | Anual -20%]** no topo
   - Preço atualiza dinâmico
   - Botão `[Assinar]` em cada card paid
3. Click "Assinar Pro" → **form de dados fiscais** (modal ou step):
   - Tipo: radio PF/PJ
   - Tax ID: CPF ou CNPJ com mask + validation (algoritmo BR)
   - **Endereço** completo:
     - CEP (com lookup ViaCEP, opcional pre-fill)
     - Rua, Número, Complemento, Bairro, Cidade, UF
4. Submit form → server action:
   - Atualiza `organizations.tax_id_type`, `tax_id`, `billing_address`
   - Chama Asaas: `createCustomer` se novo, `getCustomer` se existe
   - Chama Asaas: `createSubscription({plan, cycle, customerId})`
   - Retorna URL hosted checkout Asaas
   - Redirect user pra URL
5. **Retorno pós-pagamento:** Asaas redireciona pra `/settings/billing?success=true`
   - Mostra toast "Aguardando confirmação..."
   - Webhook (story 6.6) ativa subscription
   - Polling/refresh: re-fetch status a cada 5s por 1min
   - Quando active, banner "Pro ativo. Você tem 7 dias pra cancelar com reembolso total."
6. UI status indicators:
   - `active` → verde "Ativo até {date}"
   - `past_due` → amarelo "Pagamento pendente. [Atualizar]"
   - `cancelled` → cinza "Cancelado, ativo até {date}"
   - `expired` → vermelho "Vencido. [Reativar]"
7. **Cancel button** (visível se paid):
   - Modal contextual (depende `refund_eligible_until` — story 6.8)
   - Decision flow definido na story 6.8

## Dev notes

- **Mask:** usar `react-imask` ou string formatter próprio
- **ViaCEP:** API gratuita pra lookup CEP → preenche endereço
- **CPF/CNPJ algoritmo:** validar digit verificador (não só formato).
  Importante pra Asaas aceitar
- **Asaas hosted checkout:** retorna URL pra UI pública do Asaas com
  todas opções (PIX, cartão, boleto)
- **Polling pós-pagamento:** alternativa = WebSocket pra notify
  webhook → UI. V1 = simple polling
