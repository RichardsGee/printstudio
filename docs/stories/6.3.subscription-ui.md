# Story 6.3 — UI de Assinatura (escolher plano + checkout)

**Status:** Draft
**Epic:** 6 — Pagamentos & Monetização
**Tipo:** Frontend + API integração
**Estimativa:** 3-4 dias
**Depende de:** Story 6.1, Story 6.2

## Contexto

Fluxo do usuário pra fazer upgrade: ver planos, escolher, ir pro checkout
Asaas, voltar ativado.

## Acceptance Criteria

1. Página `/settings/billing` mostra:
   - Plano atual (com badge)
   - Próxima cobrança (data + valor)
   - Botão "Mudar plano"
2. Modal/página de seleção de plano: 3 cards (Free/Pro/Business)
3. Clique em "Assinar Pro" (ou Business):
   - Cria customer no Asaas se não existir
   - Cria subscription
   - Retorna URL de pagamento Asaas (formato hospedado)
   - Redireciona o usuário pra essa URL
4. Asaas processa pagamento → webhook (já implementado na 6.1) →
   subscription ativa
5. Página de "obrigado" após pagamento confirmado (com refresh do plano)
6. Botão "Cancelar assinatura" (downgrade pro Free no final do ciclo)
7. UI mostra status: `active`, `overdue` (com CTA pra atualizar pagamento),
   `canceled`

## Non-Goals

- Checkout embutido (usar Asaas hosted)
- Pagamento avulso (só assinatura recorrente)
- Múltiplos métodos por assinatura

## Arquivos prováveis

- `apps/web/src/app/(app)/settings/billing/billing-client.tsx`

## Dev notes

- Asaas API tem `paymentLink` que gera URL hospedada (PIX/cartão/boleto)
- Considerar mostrar QR PIX direto na UI pra plano mensal (UX mais
  rápida, mas complexidade maior)
- Após webhook ativar a subscription, refresh do plano deve ser via
  re-fetch (não tem SSE/WS de billing por enquanto)
