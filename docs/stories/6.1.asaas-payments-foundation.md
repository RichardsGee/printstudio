# Story 6.1 — Asaas SDK + ENV + webhook handler base (idempotente)

**Status:** Ready
**Epic:** 6 — Pagamentos & Monetização
**Tipo:** Backend (API)
**Estimativa:** 2d
**Depends on:** 6.2 (schema subscriptions/asaas_webhook_events deve existir)

## Contexto

Foundation da integração com Asaas: cliente HTTP, autenticação, webhook
handler base, env vars. Stories 6.3+ dependem dessa.

Decisão V1: **ENV global única** (não multi-tenant Asaas) — 1 conta
Asaas do PrintStudio.

## Acceptance Criteria

1. ENV vars (`.env.example` + EasyPanel prod):
   - `ASAAS_API_KEY` — API key da conta master (criptografar at rest? V1 ENV plain)
   - `ASAAS_API_BASE` — `https://sandbox.asaas.com/api/v3` (dev) ou
     `https://api.asaas.com/v3` (prod)
   - `ASAAS_WEBHOOK_TOKEN` — secret pra validar webhooks (HMAC ou
     header signature conforme Asaas docs)
2. Service `apps/api/src/services/asaas-client.ts`:
   - `createCustomer({ name, email, cpfCnpj, ... })`
   - `getCustomer(asaasCustomerId)`
   - `createSubscription({ customerId, plan, cycle, ... })`
   - `cancelSubscription(asaasSubId)`
   - `refundPayment(paymentId)` (pra story 6.8)
   - `getSubscription(asaasSubId)`
   - `listPayments(customerId)`
   - Retry + backoff exponencial (3 tentativas, jitter)
   - Logs estruturados com requestId
3. Webhook handler básico em `apps/api/src/routes/asaas-webhook.ts`:
   - `POST /api/asaas/webhook` aceita JSON
   - Valida assinatura header
   - Idempotency via `asaas_webhook_events.event_id` UNIQUE
   - INSERT do payload completo + timestamp
   - **Lógica de processamento por event_type vai na story 6.6**
   - Retorna 200 sempre que receber (Asaas re-envia se 5xx)
4. Logs estruturados (sem PII no payload de log)
5. `docs/architecture/asaas-integration.md` (NOVO) — design doc
   com flow + endpoints + edge cases
