# Story 6.1 — Asaas Payments Foundation

**Status:** Draft
**Epic:** 6 — Pagamentos & Monetização
**Tipo:** Backend (API)
**Estimativa:** 2-3 dias

## Contexto

Base de integração com Asaas: cliente HTTP, autenticação, webhook handler
e tabelas básicas pra registrar customer e subscription. Stories
posteriores (6.2 planos, 6.3 UI) dependem dessa.

## Acceptance Criteria

1. Schema: nova tabela `asaas_customers`
   - `id`, `org_id` (unique), `asaas_customer_id`, `created_at`
2. Schema: nova tabela `asaas_subscriptions`
   - `id`, `org_id`, `asaas_subscription_id`, `plan_id`, `status`
     (active/inactive/overdue/canceled), `next_due_date`, `created_at`,
     `updated_at`
3. Schema: nova tabela `asaas_webhook_events` (log + idempotência)
   - `id`, `asaas_event_id` (unique), `event_type`, `payload` (jsonb),
     `received_at`, `processed_at`, `error`
4. Env: `ASAAS_API_KEY`, `ASAAS_API_BASE` (sandbox vs prod),
   `ASAAS_WEBHOOK_TOKEN`
5. Cliente HTTP: `apps/api/src/services/asaas-client.ts` com métodos:
   - `createCustomer(orgId, data)`
   - `createSubscription(customerId, planConfig)`
   - `cancelSubscription(asaasSubId)`
   - `getSubscription(asaasSubId)`
6. Webhook handler: `POST /api/webhooks/asaas`
   - Valida token (header `asaas-access-token` === env)
   - Idempotência via `asaas_event_id`
   - Eventos tratados:
     - `PAYMENT_RECEIVED` → marca subscription `active`
     - `PAYMENT_OVERDUE` → marca subscription `overdue`
     - `SUBSCRIPTION_DELETED` → marca `canceled`
7. Criptografar `asaas_api_key` em rest se tiver per-tenant key.
   V1: 1 chave global (master account), sem necessidade.
8. Logs estruturados de todas as chamadas (request id, status, latência)

## Non-Goals

- UI de assinatura (Story 6.3)
- Definição de planos (Story 6.2)
- Cobrança por uso (Story 6.5)
- Multi-currency (BRL only)

## Dev notes

**Asaas API docs:** https://docs.asaas.com/

Endpoints chave:
- `POST /v3/customers` — criar customer
- `POST /v3/subscriptions` — criar assinatura recorrente
- `DELETE /v3/subscriptions/{id}` — cancelar
- Webhook config no painel Asaas

**Idempotência crítica:** Asaas pode reenviar webhook. SEMPRE checar
`asaas_event_id` antes de processar.

**Sandbox:** Asaas tem ambiente sandbox completo (https://sandbox.asaas.com).
Validar tudo lá antes de produção.
