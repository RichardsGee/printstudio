# Story 9.5 — Lista users/orgs com plan atual + última atividade

**Status:** Ready for Review (escopo V1 — DAU/MAU + sub status pendem)
**Epic:** 9 — Internal Admin Panel
**Tipo:** Frontend + Backend
**Estimativa:** 1.5d
**Depends on:** 9.1, 9.2, 8.2 (organizations schema)

## Contexto

Lista todas as orgs do sistema (1 user = 1 org no V1) com info
de gestão: plano, status sub, atividade, contagens.

## Acceptance Criteria

1. Página `/admin/orgs` com tabela:
   - Colunas: nome org, owner (email), plano, status sub (badge),
     printers count, criado_at, última atividade
2. **Filtros:**
   - Plano (free/pro/business multi-select)
   - Status subscription (multi)
   - Atividade (ativos 7d / 30d / inativos 30d+)
   - Range data signup
3. **Busca** por nome org ou email owner
4. **Métricas top:**
   - Total orgs
   - Distribuição plano (pie)
   - DAU / MAU
   - Onboarding completo % (org.onboarding_step = 'done')
5. **Click na linha** → abre detail (story 9.6) ou navega pra `/admin/orgs/{id}`
6. **Última atividade:** calcular via:
   - `MAX(printers.updated_at)` ou
   - `MAX(events.created_at WHERE org_id = ...)` ou
   - Cache em `organizations.last_activity_at` (denormalized)
   V1 = denormalize com trigger ou job cron

## Dev notes

- **Last activity:** trade-off perf vs correctness:
  - On-the-fly query: lento com muitas orgs
  - Denormalized: precisa cron pra atualizar
  - Recomendo denormalize: cron 5min atualiza `organizations.last_activity_at`
- **Pagination:** cursor-based, 50/page
- **Filtros perf:** indexes em (plan, last_activity_at), (status, ...)
- **N+1 prevention:** join com subscriptions + count printers em 1 query
  ou subquery
