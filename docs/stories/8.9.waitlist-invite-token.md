# Story 8.9 — Vincular waitlist → signup via token de convite (pre-fill)

**Status:** Ready
**Epic:** 8 — Customer Onboarding
**Tipo:** Backend + Frontend
**Estimativa:** 0.5d
**Depends on:** 8.1 (signup endpoint), 8.2 (invite_tokens schema), 9.4 (Admin panel gera token)

## Contexto

Decisão fechada PRD 8: **signup aberto** mas token de convite (gerado
pelo Admin Panel — story 9.4) **pre-fill** os campos de qualificação
no signup + linka org → waitlist via `organizations.waitlist_id`.

Mantém qualificação de leads de waitlist sem fricção de bloqueio.

## Acceptance Criteria

1. Endpoint `GET /api/invite-tokens/:token` valida token:
   - Retorna `200 { valid: true, name, email }` se válido
   - Retorna `404` se token não existe
   - Retorna `410` se expirado ou usado
2. Signup page (`/signup?invite={token}`) consome esse endpoint server-side
   no page.tsx:
   - Se 200, renderiza form com `defaultValue` pre-fill de name/email
   - Mostra badge "Convite confirmado" no topo (Mission Control style)
   - Se 4xx, renderiza form normal sem pre-fill (signup normal)
3. Signup endpoint (`POST /api/auth/signup`):
   - Aceita campo opcional `inviteToken` no body
   - Valida token novamente server-side (defesa profundidade)
   - Passa pra service `createUserWithOrg` (story 8.2) que:
     - Busca waitlist linked
     - Copia `state`, `city`, `role` pro organizations
     - Set `organizations.waitlist_id = waitlist.id`
     - Set `waitlist.status = 'converted'`
     - Marca `invite_tokens.used_at = now()`
4. Token usado uma única vez (UNIQUE check via `used_at IS NOT NULL`)
5. Token expira em **30 dias** (gerado pelo Admin Panel — story 9.4)
6. Após signup com token, profile step (story 8.3) **mostra campos
   pre-preenchidos** com region/role do waitlist

## Dev notes

- **Token format:** sugestão `nanoid(32)` ou `ulid()` — random URL-safe
- **Storage tabela `invite_tokens`:** criada na story 8.2
- **Race condition:** se 2 signups usam mesmo token simultâneo,
  `UPDATE ... WHERE used_at IS NULL` garante atomicidade
- **`waitlist.status = 'converted'`:** atualiza no INSERT bem-sucedido
  pra Admin Panel ver conversão (Epic 9)
- **404 vs 410:** semanticamente diferente (não existe vs existe-mas-vencido).
  Frontend mostra mensagem específica
- **Cross-domain:** signup é em `app.guiaprint3d.com` mas token vem
  de link compartilhado (WhatsApp/email). Garante token funciona
  cross-origin

## CodeRabbit Integration

- Foco: token validation (timing-safe compare), race conditions
  (atomic UPDATE), CSRF (token-in-URL é seguro pra GET, mas POST signup
  precisa CSRF protection padrão NextAuth)
- Severity: HIGH = warn (token vazado = acesso indevido)
