# Story 5.4 — Reordenar Impressoras (dash + kiosk)

**Status:** Draft
**Epic:** 5 — Polish & UX
**Tipo:** Fullstack
**Estimativa:** 1 dia

## Contexto

Ordem das impressoras hoje é por `createdAt` ou serial. Usuário com 4+
impressoras quer reordenar manualmente — colocar a mais usada primeiro,
agrupar por bancada física, etc.

A ordem deve afetar **tanto** o dashboard quanto o kiosk (mesma sequência).

## Acceptance Criteria

1. Schema: nova coluna `printers.sort_order` (int, default 0, nullable)
2. API: `POST /api/printers/reorder` aceita array `[{ id, sortOrder }]`
   (bulk update atômico)
3. UI: modo "reordenar" no dashboard com drag-and-drop
4. UI: ao confirmar, persiste no banco e fecha modo
5. Query default das impressoras: `ORDER BY sort_order ASC, created_at ASC`
6. Kiosk respeita a mesma ordem

## Non-Goals

- Ordenação por usuário (cada user vê uma ordem diferente). É por org.
- Grupos/categorias de impressoras (futuro)
- Reordenar via teclado (drag-and-drop só, com touch funcional)

## Arquivos prováveis

- `packages/db/src/schema.ts` — `sortOrder`
- `packages/db/migrations/0012-printer-sort-order.sql`
- `apps/api/src/routes/printers.ts` — handler reorder
- `apps/web/src/components/printers-reorder.tsx` (novo, lazy)
- Biblioteca: `@dnd-kit/sortable` (leve, acessível)

## Dev notes

- Default novo no DB pra sort_order zero — todas começam empatadas
- Tiebreaker secundário `created_at` mantém ordem estável
- Atomicidade: TX no api, todas as updates num único commit
