# Story 8.2 — Auto-create user + org + member (transação atômica)

**Status:** Draft
**Epic:** 8 — Customer Onboarding
**Tipo:** Backend + DB
**Estimativa:** 0.5d
**Depends on:** — (foundation pra 8.1 funcionar)

## Contexto

Quando lead vira user, precisa criar **3 entidades** atomicamente:
1. `users` row
2. `organizations` row (nome default "Org de {nome}")
3. `organization_members` row vinculando (role=owner)

Se qualquer falhar, rollback total. Sem inconsistência.

Schema migration também adiciona campos novos em `organizations`
relacionados ao onboarding.

## Acceptance Criteria

1. Migration drizzle aplica:
   - `organizations.onboarding_step` text DEFAULT 'profile' NOT NULL
   - `organizations.onboarding_completed_at` timestamp nullable
   - `organizations.role` text nullable (sync com waitlist_role)
   - `organizations.state` text nullable (BR UF)
   - `organizations.city` text nullable
   - `organizations.plan` text DEFAULT 'free' NOT NULL
   - `organizations.waitlist_id` uuid REFERENCES waitlist(id) ON DELETE SET NULL
   - `invite_tokens` table criada (token PK, waitlist_id FK, used_at, expires_at, created_at)
2. Service `createUserWithOrg({ email, name, passwordHash, waitlistToken? })` em
   `apps/api/src/services/signup.ts`:
   - Inicia transação drizzle (`db.transaction`)
   - INSERT user
   - Se waitlistToken válido (não expirado, not used):
     - Busca waitlist row → copia state/city/role pro org
     - Set `org.waitlist_id`
     - Marca `invite_tokens.used_at = now()`
   - INSERT organization (name = "Org de {name}", plan = 'free', onboarding_step = 'profile')
   - INSERT organization_member (user_id, organization_id, role = 'owner')
   - Commit retorna `{ user, organization, member }`
3. Se qualquer INSERT falhar, transação rollback (drizzle nativo)
4. Função throws com error code específico:
   - `EMAIL_EXISTS` se UNIQUE constraint user.email
   - `INVITE_INVALID` se token inválido/expirado/usado (mas não bloqueia
     signup — fallback pra signup sem pre-fill)
   - `INTERNAL_ERROR` qualquer outro
5. Logs estruturados: `signup.success` com user_id (não email), `signup.error` com code

## Dev notes

- **Transação drizzle:** `db.transaction(async (tx) => { ... })`. Em
  postgres-js. Rollback automático se throw
- **`waitlist_id` opcional:** se signup direto (sem token), fica NULL
- **`invite_tokens.expires_at`:** decisão = 30 dias após geração (V1 simple)
- **Org name default:** "Org de {primeiro nome}" — extrair primeiro
  nome via split(' ')[0]
- **Plan default 'free':** crítico pra Free tier funcionar imediatamente
- **Role enum:** validar contra `waitlist_role` enum existente (Epic 7)

## Schema reference

```sql
-- additions
ALTER TABLE organizations ADD COLUMN onboarding_step text DEFAULT 'profile' NOT NULL;
ALTER TABLE organizations ADD COLUMN onboarding_completed_at timestamptz;
ALTER TABLE organizations ADD COLUMN role text;
ALTER TABLE organizations ADD COLUMN state text;
ALTER TABLE organizations ADD COLUMN city text;
ALTER TABLE organizations ADD COLUMN plan text DEFAULT 'free' NOT NULL;
ALTER TABLE organizations ADD COLUMN waitlist_id uuid REFERENCES waitlist(id) ON DELETE SET NULL;

CREATE TABLE invite_tokens (
  token text PRIMARY KEY,
  waitlist_id uuid REFERENCES waitlist(id) ON DELETE CASCADE,
  used_at timestamptz,
  expires_at timestamptz NOT NULL,
  created_at timestamptz DEFAULT now() NOT NULL
);
CREATE INDEX invite_tokens_waitlist_idx ON invite_tokens (waitlist_id);
```
