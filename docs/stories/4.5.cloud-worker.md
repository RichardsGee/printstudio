# Story 4.5 — Cloud Worker (apps/worker)

**Status:** InProgress (MVP)
**Epic:** 4 — Cloud-only mode
**Tipo:** Service
**Estimativa:** 1 semana (MVP entregue em ~3h)

## Contexto

POC 4.1 provou conexão Bambu Cloud. Story 4.4 entregou UI pra usuário
conectar conta. Falta agora a peça que **substitui o bridge LAN**: um
serviço que rode 24/7 no EasyPanel, conecte no MQTT cloud da Bambu, e
relaye telemetria pro api (mesma rota `/ws/bridge` que o bridge LAN usa).

Sem este worker, o user até consegue conectar a conta na UI, mas nenhum
dado entra no DB cloud-only.

## Acceptance Criteria

1. Novo workspace `apps/worker/` com:
   - `package.json` (workspace)
   - `tsconfig.json`
   - `Dockerfile` (multi-stage com esbuild bundle, mesmo padrão do api)
   - `.env.example`
2. Worker lê `bambu_credentials` da org configurada, decripta tokens
3. Worker chama Bambu Cloud `user/bind` e faz upsert dos devices em `printers`
   (org-scoped, serial como chave natural)
4. Worker conecta `mqtts://us.mqtt.bambulab.com:8883` com `u_{userId}` + JWT
5. Worker subscreve `device/{serial}/report` de cada device
6. Worker conecta `/ws/bridge` do api com `bridge.hello` (token compartilhado)
7. Cada mensagem MQTT → PrinterState → `bridge.state` pro api
8. `pnpm --filter @printstudio/worker typecheck` passa
9. `pnpm --filter @printstudio/worker build` gera bundle único em `dist/index.js`

## Non-Goals (próximas stories)

- ❌ Token refresh automático (a Bambu refresh endpoint tá quebrado; usar re-login via UI)
- ❌ Multi-org num único worker (1 worker = 1 org no MVP)
- ❌ Comandos remotos (pause/resume/stop via MQTT publish do cloud)
- ❌ Hot-reload de credenciais ao usuário re-conectar via UI (precisa restart)
- ❌ Câmera via TUTK cloud (Story 4.7)

## Deploy no EasyPanel

Criar service `worker`:

| Config | Valor |
|---|---|
| Source | mesmo repo, branch main |
| Build Method | Dockerfile |
| Dockerfile Path | `apps/worker/Dockerfile` |
| Build Context | `/` (raiz) |
| Port | **(none — não expõe HTTP)** |
| Restart Policy | `on-failure` (worker é stateful — restart quando crash) |

Env vars (copiar de `.env.production.worker`):
- `DATABASE_URL` (mesma do api)
- `BAMBU_CRED_KEY` (mesma do api — pra decryptar)
- `CLOUD_WS_URL` (URL do api do EasyPanel: `wss://api.../ws/bridge`)
- `CLOUD_API_TOKEN` (mesmo do api)
- `WORKER_ID=worker-cloud-01`
- `ORGANIZATION_ID=00000000-0000-0000-0000-000000000001` (org Default)

## Pré-requisitos pra rodar

1. User precisa ter conectado a conta Bambu via UI Story 4.4 (`/settings/bambu-connect`)
2. `bambu_credentials` da org tem que existir no DB
3. Impressoras precisam estar em modo Cloud (não LAN-only)
4. Token Bambu ainda válido (não expirou)

## Smoke test

```bash
# Local
cd apps/worker
cp .env.example .env
# preencher BAMBU_CRED_KEY, DATABASE_URL etc

pnpm dev
```

Esperado nos logs (em ordem):
- `worker starting`
- `credentials loaded`
- `devices bound to account`
- `printers sync done`
- `cloud relay connecting` → `connected`
- `cloud MQTT connecting` → `connected`
- `subscribed report`
- (após pushall) `state` emit pra cada device → relay envia pro api

No api do EasyPanel, log deve mostrar:
- `bridge authenticated` (vindo do worker)

Na UI do web, telemetria deve aparecer ao vivo no dashboard.
