# Story 9.9 — Audit log de ações admin (lista + detalhe)

**Status:** Ready
**Epic:** 9 — Internal Admin Panel
**Tipo:** Backend + Frontend
**Estimativa:** 1d
**Depends on:** 9.1 (admin foundation)

## Contexto

Toda ação destrutiva ou sensitive no Admin Panel precisa **gerar
audit log** (decisão fechada PRD 9). Compliance + debugging.

Schema base + UI pra ver/filtrar.

## Acceptance Criteria

1. Migration aplica schema `admin_audit_log`:
   ```sql
   CREATE TABLE admin_audit_log (
     id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
     admin_user_id uuid NOT NULL REFERENCES users(id),
     action text NOT NULL,
     target_type text NOT NULL,
     target_id uuid,
     payload jsonb,
     ip_address inet,
     created_at timestamptz DEFAULT now() NOT NULL
   );
   CREATE INDEX admin_audit_log_admin_idx ON admin_audit_log (admin_user_id, created_at DESC);
   CREATE INDEX admin_audit_log_target_idx ON admin_audit_log (target_type, target_id);
   ```
2. Helper `logAdminAction({ action, targetType, targetId, payload })`
   em `apps/web/src/lib/admin-audit.ts`:
   - Pega admin_user_id da session
   - Pega ip_address do request
   - INSERT async
3. **Chamado em todas as ações:**
   - Story 9.3: marcar status, tag, notes update
   - Story 9.4: invite_generated
   - Story 9.5/9.6: plan_changed, suspend, soft_delete
   - Story 9.7: refund_manual, mark_paid, force_charge
4. Página `/admin/audit` com:
   - Tabela paginada (50/page)
   - Colunas: timestamp, admin (email), action, target_type,
     target_id (linka pro entity), payload (preview)
   - Click expansível pra ver payload JSON completo formatted
5. **Filtros:**
   - Action (multi-select tipos existentes)
   - Target type (waitlist/user/org/subscription)
   - Range de data
   - Admin (V1 single admin, V2 multi)
6. **Retention:** sem delete V1. V2 archive >90d
7. **Read-only:** não editável via UI

## Dev notes

- **Async insert:** fire-and-forget pra não bloquear request. Log
  warning se falhar
- **Payload structure:** sugestão `{ before: {...}, after: {...},
  justification?: string, ...metadata }`
- **IP detection:** mesma estratégia da story 7.3 (X-Forwarded-For)
- **JSON preview:** UI mostra primeiras 100 chars + expand pra full
- **Audit completeness target:** 100% das ações destrutivas geram
  entry. Check via query no QA

## CodeRabbit Integration

- Foco: PII no payload (sanitize antes de log), audit gaps
  (todo destructive deve logar), performance (sem bloqueio)
- Severity: CRITICAL = block (audit gap = compliance fail)
