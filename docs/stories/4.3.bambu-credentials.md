# Story 4.3 — bambu_credentials + cripto

**Status:** InProgress
**Epic:** 4 — Cloud-only mode
**Tipo:** Foundation / Security
**Estimativa:** 2 dias

## Contexto

POC 4.1 validou que o login Bambu retorna um JWT que precisa ser
guardado pra reusar nas próximas requisições (sem fazer o user pedir
código por email toda vez). Esse JWT é **credencial sensível** — quem
tiver ele acessa a conta Bambu inteira: pode ver, pausar, cancelar prints,
e ler histórico do MakerWorld.

Esta story cria a infraestrutura pra armazenar esses tokens **criptografados
em repouso** no Postgres, indexados por organização (Story 4.2).

## Acceptance Criteria

1. Tabela `bambu_credentials` criada:
   - `id` uuid PK
   - `organization_id` uuid FK UNIQUE (1 conta Bambu por org no v1)
   - `bambu_email` text NOT NULL
   - `bambu_user_id` text NOT NULL (ex: "343300405")
   - `encrypted_access_token` bytea NOT NULL
   - `encrypted_refresh_token` bytea (nullable — Bambu pode não devolver)
   - `access_token_expires_at` timestamptz NOT NULL
   - `last_synced_at` timestamptz (quando rodou login mais recente)
   - `created_at`, `updated_at`
2. Helpers `encrypt()` / `decrypt()` em `packages/db/src/crypto.ts`:
   - AES-256-GCM
   - Random nonce de 12 bytes por encryption
   - Output: `nonce || ciphertext || authTag` em Buffer
3. Função aceita chave de 32 bytes (lida do env `BAMBU_CRED_KEY` na camada que usa)
4. Test unitário cobrindo encrypt → decrypt round-trip + tamper detection
5. Env `BAMBU_CRED_KEY` documentado em `.env.production.api` (com placeholder)
6. Migration aplicada em prod (EasyPanel Postgres)
7. `pnpm --filter @printstudio/db typecheck` passa

## Non-Goals

- ❌ Lógica de refresh do token (Story 4.5 — quando o worker estiver rodando)
- ❌ UI pra conectar conta Bambu (Story 4.4)
- ❌ Múltiplas contas Bambu por org (v2 — começa 1:1)

## Notas de segurança

- A `BAMBU_CRED_KEY` é a chave mestra — vazá-la equivale a vazar TODOS os
  tokens encryptados. Rotacionar é doloroso (precisa re-encriptar tudo).
- Em runtime, decryption acontece SÓ no momento de usar o token (pra fazer
  request HTTP/MQTT pra Bambu). Plaintext nunca é persistido.
- A chave fica como env var do service `api` no EasyPanel — não vai pro git.
