# Story 9.6 — Detalhe da org (printers, members, subscription, eventos, audit)

**Status:** Ready for Review (escopo V1 — suspend/delete/Asaas pendem)
**Epic:** 9 — Internal Admin Panel
**Tipo:** Frontend + Backend
**Estimativa:** 1.5d
**Depends on:** 9.5 (lista de orgs)

## Contexto

Drill-down completo de uma org específica. View admin com abas pra
ver tudo + tomar ações.

## Acceptance Criteria

1. Página `/admin/orgs/[id]` com header info (nome, plano, status,
   datas, tax_id, endereço se preenchido)
2. **Abas:**
   - **Info** (default): dados básicos editáveis (nome, plano manual,
     suspender)
   - **Members**: lista users da org com role
   - **Printers**: impressoras vinculadas com status atual
     (online/offline) e última atividade
   - **Subscription**: histórico cobranças (subscription_invoices),
     próxima fatura, métodos pagamento
   - **Eventos**: log de eventos recentes (events table, 50 mais
     recentes)
   - **Audit**: ações admin sobre essa org específica
3. **Ações** (na aba Info):
   - **Mudar plano manual** (super_admin override): dropdown free/pro/
     business + textarea justificativa (obrigatória) → gera audit log
     com payload before/after
   - **Suspender conta** (soft-delete): marca `org.status = 'suspended'`,
     bloqueia login dos members. Reversível
   - **Soft-delete** (deletar): mais agressivo, confirma 2x. Reversível
     por 30d via DB
4. **Server-side auth:** todas ações revalidam super_admin
5. Audit log entry pra cada ação destrutiva (mudança de plano,
   suspensão, delete)

## Dev notes

- **Tabs implementation:** Radix UI Tabs (já disponível? senão custom
  com state)
- **Plan change manual:** **gera audit + dispara webhook Asaas** pra
  sync se subscription existe (caso especial — admin força override
  do gateway). V1 = só atualiza DB, V1.1 sync com Asaas
- **Suspend vs delete:** suspend = reversível 1-click. Delete = soft
  (org.deleted_at = now()) reversível 30d, depois hard delete via cron
- **Justificativa obrigatória:** texto livre 10+ chars, salvo no audit
  log payload pra compliance
- **N+1 prevention:** Server component faz 1 query principal +
  prefetch das abas se cara (members, printers já são pequenos)
