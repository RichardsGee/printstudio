# Story 6.8 — Reembolso CDC 7d (auto-refund se cancelar nos primeiros 7d)

**Status:** Draft
**Epic:** 6 — Pagamentos & Monetização
**Tipo:** Backend + Frontend
**Estimativa:** 1d
**Depends on:** 6.6 (webhook + schema refund_eligible_until)

## Contexto

Decisão fechada PRD 6: **honra CDC art. 49** (7 dias arrependimento
integral). User que cancela nos primeiros 7d → reembolso total
automático. Após = sem reembolso, serviço continua até fim do ciclo.

Reduz risco legal e melhora confiança.

## Acceptance Criteria

1. Quando user cancela em `/settings/billing`:
   - Server-side check: `NOW() <= subscription.refund_eligible_until`?
   - **SE SIM (dentro de 7d):**
     - Modal: "Você está nos primeiros 7d. Reembolso integral pelo CDC.
       Confirmar cancelamento + reembolso?"
     - `[Confirmar + receber reembolso]` `[Voltar]`
     - Submit → server action `cancelWithRefund(subId)`
   - **SE NÃO (após 7d):**
     - Modal: "Serviço continua até {current_period_end}. Sem reembolso
       após 7d."
     - `[Confirmar cancelamento]` `[Voltar]`
     - Submit → server action `cancelAtPeriodEnd(subId)`
2. `cancelWithRefund(subId)`:
   - Call Asaas API: refund da última cobrança (full amount)
   - Update `subscriptions.status = 'refunded'`
   - Update `subscription_invoices.refunded_at + refund_reason = 'cdc_7d'`
   - Downgrade `organizations.plan = 'free'` imediato
   - Trigger story 6.5 archive flow (printers excedentes)
   - Audit log entry `subscription.refunded_cdc_7d`
3. `cancelAtPeriodEnd(subId)`:
   - Atualiza `cancel_at_period_end = true`
   - Status fica 'active' até period_end
   - Webhook SUBSCRIPTION_CANCELED finaliza depois (story 6.6)
4. UI feedback:
   - Refund: "Cancelado + reembolso solicitado. Crédito em até 7 dias úteis"
   - At period end: "Acesso Pro até {date}. Sem renovação automática."
5. Refund Asaas falha? Fila de retry + alerta admin (Epic 9)

  fora de estabelecimento (online). Online SaaS conta. PrintStudio
  honrar fortalece marca + reduz risco legal
- **refund_eligible_until:** set automaticamente no webhook

  Provavelmente `POST /payments/{id}/refund`
- **Retry queue V1:** se Asaas refund falha, salva pending refund em
  tabela + cron tenta 3x. Se permanece falha, alerta Richard
