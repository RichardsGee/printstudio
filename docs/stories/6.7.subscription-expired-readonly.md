# Story 6.7 — Bloqueio gracioso quando assinatura vence (modo somente-leitura)

**Status:** Ready
**Epic:** 6 — Pagamentos & Monetização
**Tipo:** Backend + Frontend
**Estimativa:** 1d
**Depends on:** 6.6 (webhook handler dispara state)

## Contexto

Quando subscription vence (past_due → expired após 7d grace), app
não deve simplesmente **quebrar**. Modo **somente-leitura**: user vê
seus dados mas não cria novos prints, não recebe webhooks, não
acessa Pro features.

## Acceptance Criteria

1. Quando `subscriptions.status = 'expired'`:
   - Org volta pra `plan = 'free'` automaticamente
   - Free tier limits aplicam (1 impressora ativa máx)
   - Impressoras excedentes viram **archived** (story 6.5 flow)
2. Banner persistente em **todas as rotas** `(app)`:
   - "⚠ Sua assinatura está vencida. [Atualizar pagamento →]"
   - Cor danger (vermelho) — não warning
3. Endpoints **bloqueiam ações Pro:**
   - POST `/api/webhooks` (configurar webhook user) → 402 PAYMENT_REQUIRED
   - GET `/api/printers` retorna apenas non-archived (free limit)
   - PATCH/POST de novos prints OK (printer ativa continua funcionando)
4. **Modo leitura** dos dados antigos preservado por 90d (período
   archive). User pode ver mas não acrescentar
5. Cron job 1x/dia:
   - Checa subscriptions com `current_period_end < NOW() - 7 days`
   - Marca como `expired`
   - Trigger flow de archive
6. Recuperação: se user paga (webhook PAYMENT_CONFIRMED), unarchive
   imediato + status volta active

## Dev notes

- **Grace period 7d:** standard SaaS. Permite user pagar atrasado
- **Não delete imediato:** preserva data 90d. UX importante: user
  que esqueceu pagar não perde tudo
- **Feature gates:** middleware checa plan + status antes de cada
  endpoint Pro. Cache 60s
- **Recovery:** quando paga, webhook handler já cuida (story 6.6).
  Esta story só implementa o **bloqueio**, não a recuperação
