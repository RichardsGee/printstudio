# Story 5.3 — Renomear Impressora (nome custom + fallback original)

**Status:** Draft
**Epic:** 5 — Polish & UX
**Tipo:** Fullstack (DB + API + UI)
**Estimativa:** 1 dia

## Contexto

Hoje o nome da impressora é o que vem da Bambu Cloud (`device.name`,
algo como "3DP-XXX-XYZ"). Usuário quer renomear pra "Impressora Loja A"
ou "Bancada Esquerda" sem perder a referência ao nome original.

Decisão: armazenar nome custom em campo separado, fallback pro nome
original Bambu quando vazio. Toggle na UI pra mostrar nome original
(útil pra debug e identificação no app Bambu).

## Acceptance Criteria

1. Schema: nova coluna `printers.display_name` (text, nullable)
2. Schema: coluna existente `name` continua sendo o nome Bambu (auto-update do worker)
3. API: `PATCH /api/printers/{id}` aceita `displayName` (string ou null)
4. API: validação org-scoped — usuário só pode renomear impressoras
   da própria org
5. UI: botão de editar no header da página da impressora
6. UI: modal/inline edit pra setar nome custom
7. UI: dashboard, kiosk e todas as listas mostram `displayName ?? name`
8. UI: tooltip ou seção "info" mostra o nome original Bambu se diferente
9. Sem migration manual no banco — automático via drizzle migrate

## Non-Goals

- Permissões granulares de quem pode renomear (todos os membros da org podem)
- Histórico de mudanças de nome
- Renomear no app Bambu (só local no PrintStudio)

## Arquivos prováveis

- `packages/db/src/schema.ts` — adicionar `displayName`
- `packages/db/migrations/0011-printer-display-name.sql` (auto-gerado)
- `apps/api/src/routes/printers.ts` (ou onde estiver) — handler PATCH
- `apps/web/src/components/printer-rename-dialog.tsx` (novo)

- Aproveitar e usar `displayName ?? name` em todos os lugares que mostram
