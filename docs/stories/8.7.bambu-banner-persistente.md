# Story 8.7 — Banner persistente "vincule sua Bambu" quando skip

**Status:** Ready for Review
**Epic:** 8 — Customer Onboarding
**Tipo:** Frontend
**Estimativa:** 0.5d
**Depends on:** 8.4 (skip flow existe)

## Contexto

Decisão fechada PRD 8: skip Bambu Connect permitido **com banner
persistente** lembrando user de vincular. Reduz risco de conta zumbi.

Banner aparece em todas as páginas do `(app)` quando user pulou ou
não completou Bambu Connect.

## Acceptance Criteria

1. Componente `<NoBambuBanner>` em `apps/web/src/components/`:
   - Renderiza só se `org.onboarding_step IN ('skipped', 'bambu_connect')`
   - Cor warning amarelo (`bg-warning/15 border-warning/40`)
   - Texto: "⚠ Sua conta não tem impressora vinculada"
   - CTA: `[Conectar agora →]` linka pra `/settings/bambu-connect`
   - Dismissível? **NÃO V1** — persistente forçado (UX deliberadamente
     persistente até user resolver)
2. Banner aparece **em todas as rotas** do `(app)/layout.tsx`:
   - `/dashboard`
   - `/kiosk`
   - `/history`
   - `/events`
   - `/settings/*`
   - `/printers/[id]`
3. **Não aparece** se:
   - User não logado
   - `org.onboarding_step == 'done'`
   - User tem pelo menos 1 impressora ativa (`printers` count > 0)
4. Visual Mission Control consistente: `data-mc-banner`, font mono,
   uppercase tracking-wider
5. Após user vincular Bambu E adicionar 1+ impressora, banner some
   automaticamente (server component re-render)

### Decisões

- **Heurística mais simples que AC:** AC #1 dizia "step IN
  ('skipped', 'bambu_connect')". AC #3 dizia "não aparece se step=='done'
  OU printerCount>0". Os 2 conflitam num caso (ex: step='profile'
  travado). Optei pela regra unificada `!onboardingDone &&
  printerCount === 0` — cobre todos os cenários do AC e é fácil de
  raciocinar.
- **1 query com JOIN + COUNT** em vez de 2 queries separadas: evita
  round-trip extra em **todo request autenticado**. Performance crítica
  pq layout renderiza em todas as páginas.
- **GROUP BY explícito** pra MAX postgres não chiar com `printers.id`
  na agregação.
- **Server Component direto no layout** sem React cache: cada request
  do layout (RSC) re-executa a query — mas TTL natural é o request,
  então ok V1. V2 pode adicionar `cache()` ou Edge cache se hot.
- **Banner no `(kiosk)` layout também:** AC #2 explicit. No cenário
  comum (kiosk de parede com impressoras já cadastradas) o banner
  nunca aparece, então sem custo visual real. Quando aparece, é
  sinal que algo está faltando — mensagem útil.
- **`data-mc-banner` attribute:** padrão Mission Control pra futuros
  selectors CSS específicos ou testes E2E.
- **Não dismissível:** PRD 8 fechou — banner persistente força ação.
  Se virar problema UX em produção, V1.1 adiciona cooldown.
