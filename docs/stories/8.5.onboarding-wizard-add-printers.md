# Story 8.5 — Onboarding wizard step 3 — auto-add printers detectadas (skippable)

**Status:** Ready for Review
**Epic:** 8 — Customer Onboarding
**Tipo:** Frontend + Backend
**Estimativa:** 1.5d
**Depends on:** 8.4 (Bambu vinculado), 8.6 (free tier enforce max 1)

## Contexto

Último step do wizard. Após vincular Bambu Cloud, listar impressoras
detectadas e permitir user selecionar **qual cadastrar**. Free tier
permite só **1 impressora** — selection enforced.

Resolve dor real: hoje precisa POST manual via API pra cadastrar
cada impressora.

## Acceptance Criteria

1. Página `/onboarding/add-printers` em `apps/web/src/app/onboarding/add-printers/page.tsx`
2. Server component:
   - Verifica `onboarding_step == 'add_printers'`
   - Busca impressoras Bambu detectadas via API existente
     (`/api/bambu/devices` ou similar — verificar nome do endpoint)
   - Renderiza lista
3. Lista de impressoras:
   - Pra cada device: card com imagem placeholder + nome editável + model + serial
   - **Free tier:** radio button (não checkbox) — só 1 selecionável
   - Pre-selected = primeira impressora
   - Nome editável inline (default = nome Bambu, user pode customizar)
4. Submit `[Adicionar impressora]`:
   - Server action `addPrintersFromBambu(selected: { serial, name }[])`
   - INSERT na tabela `printers` com `organization_id` do user
   - Atualiza `org.onboarding_step = 'done'`
   - Set `org.onboarding_completed_at = now()`
   - Redirect `/kiosk`
5. **Botão skip:** `[Pular — adicionar depois]`
   - Mesma lógica que skip Bambu (story 8.4): step = 'skipped'
   - Redirect `/dashboard` com banner (story 8.7)
6. Empty state: se Bambu vinculou mas não retornou nenhuma device:
   - Mensagem "Nenhuma impressora encontrada na sua conta Bambu Cloud"
   - CTA `[Voltar pra Bambu Connect]` ou `[Pular]`
7. Layout: PageHeader `id="ONBOARDING-3/3"`, título "Quais impressoras monitorar?"
8. Progress: `[✓] Perfil → [✓] Bambu → [●] Impressoras`

### Decisões

- **Path `/onboarding/add-printers` (conforme AC #1):** seguia AC
  literal, mesmo que `/onboarding/printers` fosse mais curto.
  Mantém consistência com o resto da story.
- **Free tier enforce em 2 camadas:**
  - UI: input type='radio' (HTML semântico bloqueia múltipla
    seleção) + `toggleSelection` força `next.clear()` antes de
    adicionar quando isFree.
  - Backend: server action checa `org.plan === 'free' &&
    selections.length > 1` → erro `FREE_TIER_LIMIT`.
- **Pre-select primeira impressora:** UX inicial é "tem 1 selected
  por default" — user só desmarca/troca se quiser. Reduz cliques
  pro happy path mais comum.
- **Display order incremental:** `MAX(display_order) + 1` da org,
  ou 0 se vazio. Permite o user adicionar mais impressoras depois
  sem conflito de ordem.
- **`onConflictDoNothing` em `(org, serial)`:** se user reenviar
  por algum motivo, não dupla. UNIQUE constraint já existe no
  schema (`uqOrgSerial`).
- **`accessCode: ''` (string vazia) pros novos printers:** segue
  exatamente o padrão do `apps/worker/src/printer-registry.ts` —
  cloud-managed, auth via JWT no MQTT, não usa access_code LAN.
- **Skip + completed_at:** mesma semântica da Story 8.4 (state
  'skipped' não está em STEP_PATHS, mas `completed_at != null`
  faz layout redirecionar `/dashboard` automaticamente).
- **Server Component faz fetch via cookies:** o endpoint
  `/api/bambu/devices` exige session do backend (`SESSION_COOKIE`).
  Server Component lê todos os cookies do request, monta header
  `cookie:` e encaminha — funciona porque o navegador setou esse
  cookie no signup (Story 8.1).
- **Decripta token no endpoint, não no service:** decisão pra
  manter o crypto isolado no API. Falha de decrypt loga error
  mas não vaza detalhes pro client.
- **Token expirado (401) ≠ token vazio (404):** UI diferencia.
  Quando expirado, redireciona pro `/onboarding/bambu-connect`
  (CTA "Reconectar Bambu") em vez de mostrar empty state.
