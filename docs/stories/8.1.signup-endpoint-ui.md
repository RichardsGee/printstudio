# Story 8.1 — Signup endpoint + UI `/signup` (email/senha/termos + rate limit)

**Status:** Ready for Review
**Epic:** 8 — Customer Onboarding
**Tipo:** Frontend + Backend
**Estimativa:** 1d
**Depends on:** 8.2 (transação user+org+member precisa existir)

## Contexto

Primeiro touch do visitor pra virar user. Decisão fechada PRD 8:
**signup público aberto** (sem token obrigatório), token de convite
apenas pre-fill se vier de waitlist.

NextAuth credentials já existe pra login, mas NÃO tem endpoint de
registration. Esta story adiciona o "sign up" lado a lado com o login.

## Acceptance Criteria

1. Página `/signup` em `apps/web` (mesmo app autenticado, rota pública)
2. Form com campos:
   - Nome* (text, min 2 chars, max 100)
   - Email* (email format, lowercase, UNIQUE check)
   - Senha* (min 12 chars, mostrar requisitos: maiúscula + número + especial)
   - Confirmar senha (must match)
   - Checkbox: "Aceito [termos](#) e [política de privacidade](#)"* (links abrem em nova aba)
   - Submit `[Criar conta]` com loading state
3. Se URL tem `?invite={token}` válido (story 8.9):
   - Pre-fill `name` e `email` da waitlist linked
   - Mostra badge "Convite confirmado" no topo
4. Endpoint `POST /api/auth/signup` em `apps/api` ou route handler Next.js:
   - Valida Zod schema server-side
   - Hash senha com bcrypt (12 rounds) ou argon2 (já no projeto)
   - Chama transação atômica (story 8.2)
   - Set NextAuth session cookie automaticamente após signup OK
   - Redirect pra `/onboarding/profile`
5. Rate limit: max 5 signups / IP / hora → 429
6. Honeypot field invisible (mesma estratégia Epic 7)
7. Errors inline:
   - Email já cadastrado: "Esse email já tem conta. [Fazer login →]"
   - Senha fraca: lista qual requisito falta
   - Termos não aceitos: bloqueia submit
8. Acessibilidade: form com labels, aria-required, focus management

- **NextAuth credentials:** já tem login com email/senha. Signup é
  adição. NextAuth não tem signup nativo (precisa endpoint custom)
- **Argon2:** já no `apps/web` (package.json tem argon2). Reusar
- **Session cookie:** após criar user + org, gerar JWT NextAuth ou
  redirect pra `/api/auth/callback/credentials` automaticamente
- **Pre-fill via token:** server component `page.tsx` lê
  `searchParams.invite` → busca em `invite_tokens` → renderiza form

### Decisões

- **Rate limit em memory (Map IP → timestamps[]):** decisão pragmática
  V1. EasyPanel roda 1 instância, memory cache funciona. Cleanup
  agendado via `setInterval(5min).unref()` evita leak. V2 com
  múltiplas instâncias migra pra Redis.
- **Honeypot 200 fake silencioso:** mesma estratégia do waitlist
  (Story 7.3). Bot não sabe que foi pego, não tenta de novo.
- **Endpoint público separado pra invite resolve:** em vez de pôr
  o pre-fill na própria página `/signup` server-side (que teria
  que importar `db` direto), criei `GET /api/public/invite/:token`
  no apps/api. Vantagens:
  1. Server Component da `/signup` usa fetch padrão (cacheable)
  2. Centraliza lógica em 1 lugar (mesmo da invalidação)
  3. Permite que sites externos (ex: futuro app mobile) reusem
- **Não consume token no GET endpoint:** consume real só acontece
  na transação do signup (race-safe). Endpoint público apenas valida
  + retorna pre-fill.
- **NextAuth signIn pós-signup:** o backend set cookie próprio (sessions
  table), mas o NextAuth do apps/web usa JWT separado. Pós POST OK,
  chamo `signIn('credentials', { redirect: false })` pra popular o
  JWT também. Os dois sistemas coexistem sem conflito.
- **Placeholder /onboarding/profile dentro do (app) group:** garante
  que o middleware de auth (`AppLayout` redirect `/login`) protege a
  rota. Conteúdo é placeholder com link "Ir pro dashboard" pra
  destrava enquanto Story 8.3 não chega.
- **Password strength visual:** 4 regras (12 chars, maiúscula, número,
  especial) com check/X verde/cinza atualizando em tempo real. Sem
  toast de erro pra senha — feedback inline.
- **Honeypot retorna response shape válida** (com user/org com UUID
  zero) — mantém type-safety no client (não precisa branch especial
  pra esse caso, e bot não consegue distinguir de signup real).
