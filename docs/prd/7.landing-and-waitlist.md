## Motivação

Pra virar produto comercial, PrintStudio precisa validar mercado **antes**
de investir em signup público + billing. Decisão estratégica:
**"landing + waitlist primeiro, signup completo depois"** — captura interesse
qualificado, aprende ICP real, gera lista pra warm-launch quando o produto
estiver pronto.

Waitlist é **CRM-light** desde dia 1 (não fila silenciosa): leads são
qualificados (região, role, contato), etiquetados (tags + status), e
gerenciados via Admin Panel (Epic 9).

Comunidade ativa (Telegram/WhatsApp) é importante mas adiada pra **V1.1**
pra simplificar Phase 1.

## Goals

1. Landing page pública profissional comunicando o valor de PrintStudio
   em `guiaprint3d.com`
2. Form de waitlist **rico** capturando leads qualificados (email, nome,
   região, role, bambu_count, contato extra opcional)
3. Storage interno como CRM-light (DB) sem dependência de email provider
   em V1
4. Tracking de fonte (UTM params) pra entender canais
5. Defesa anti-spam sem fricção (honeypot + rate limit, sem captcha)

## Decisões fechadas

- **Domínio:** `guiaprint3d.com` (a registrar — não printstudio.com.br).
  App autenticado fica em subdomínio: `app.guiaprint3d.com`
- **Stack do site:** Next.js separado em `apps/marketing/` (reaproveita
  Tailwind + tokens Mission Control)
- **Hospedagem:** **EasyPanel** (consistência com api/web/worker)
- **Demo asset:** GIF/WebP animado do kiosk em ação (loop 10-20s)
- **CTA secundário:** **"Ver demo"** → modal/seção com video YouTube
  embedded (~60s)
- **Política de privacidade + termos:** Template open-source
  LGPD-compliant adaptado pra PrintStudio
- **Email transactional:** NÃO em V1. Lead recebe success page com
  "Você está na lista." Sem email automático
- **Comunidade (Telegram/WhatsApp/Bot admin):** **Adiado V1.1**.
  Phase 1 sem integração de canais. Configurar canais + integrar depois
  quando waitlist tiver volume
- **Geolocate IP:** Skip V1. IP guardado só pra rate limit anti-spam
- **Anti-spam:** Honeypot field invisible + rate limit por IP
- **Compliance LGPD:** Mínimo — checkbox opt-in obrigatório + link pra
  política simples + termo

## Schema (story 7.3) — CRM-light

```sql
CREATE TYPE waitlist_status AS ENUM (
  'new',          -- recém cadastrado
  'contacted',    -- Richard fez primeiro contato
  'engaged',      -- respondeu, interagindo
  'invited',      -- recebeu link de signup (Epic 8)
  'converted',    -- virou user real
  'lost'          -- não respondeu / desistiu
);

CREATE TYPE waitlist_role AS ENUM (
  'hobbyist',     -- 1 Bambu casa
  'small_shop',   -- print shop pequena 1-3 imp
  'studio',       -- estudio prototipagem 4-10
  'business',     -- operação 11+ impressoras
  'other'         -- outros (eg. educação, comunidade maker)
);

CREATE TABLE waitlist (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  email text NOT NULL UNIQUE,
  name text NOT NULL,
  bambu_count integer NOT NULL CHECK (bambu_count >= 0),

  -- Qualificação
  role waitlist_role NOT NULL DEFAULT 'other',
  state text,                          -- 'SP', 'RJ', 'MG', etc (ISO 3166-2:BR)
  city text,

  -- Comunidade (V1: opcional, V1.1: usado pra convites)
  telegram_handle text,                -- @username opcional
  phone text,                          -- pra WhatsApp opcional

  -- CRM
  status waitlist_status NOT NULL DEFAULT 'new',
  tags text[] DEFAULT '{}' NOT NULL,
  notes text,
  contacted_at timestamp with time zone,
  last_contact_at timestamp with time zone,

  -- Tracking + anti-spam
  source_utm jsonb,                    -- {utm_source, utm_medium, utm_campaign, utm_content, utm_term}
  referrer text,
  user_agent text,
  ip_address inet,                     -- pra rate limit (3 cadastros/IP/hora)

  created_at timestamp with time zone DEFAULT now() NOT NULL,
  updated_at timestamp with time zone DEFAULT now() NOT NULL
);

CREATE INDEX waitlist_created_at_idx ON waitlist (created_at DESC);
CREATE INDEX waitlist_status_idx ON waitlist (status, created_at DESC);
CREATE INDEX waitlist_state_idx ON waitlist (state) WHERE state IS NOT NULL;
CREATE INDEX waitlist_tags_idx ON waitlist USING gin (tags);
CREATE INDEX waitlist_ip_recent_idx ON waitlist (ip_address, created_at DESC);
```

## Anti-spam (story 7.3)

**Honeypot field:**
```html
<input type="text" name="website" tabindex="-1"
       autocomplete="off" style="position:absolute;left:-9999px"
       aria-hidden="true">
```
Server-side: se `website` veio preenchido, retorna 200 OK falso
(sem inserir). Bot pensa que deu certo, não tenta de novo.

**Rate limit:** max **3 cadastros / IP / hora**. Excedente retorna
429. Tracking via `ip_address` no DB com `created_at` filter.

**Validação básica:** email format, nome >= 2 chars, bambu_count int.
Sem CAPTCHA visível (fricção alta).

## Riscos

- **DNS / hospedagem custos:** guiaprint3d.com não registrado ainda.
  Registro.br ~R$40/ano. DNS pode levar 24h propagar
- **Spam apesar de honeypot+rate-limit:** se bots adaptarem, adicionar
  reCAPTCHA invisible V1.5
- **Duplicate email:** UNIQUE constraint protege, retorna 409 amigável
  ("Você já está na lista, vamos te chamar em breve")
- **Sem confirmação por email:** lead pode esquecer que se cadastrou.
  Mitigação: Richard contata em <7d (V1), <2d (com Epic 9)
- **LGPD com telefone/IP:** dados pessoais sensíveis. Política precisa
  declarar uso (contato comercial), não vender, retention policy
- **Drift entre marketing e app:** se tema Mission Control evoluir, dois
  lugares pra atualizar. Mitigação: componentes shared em `packages/ui`
  no futuro (não V1)
