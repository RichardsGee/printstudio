# PRD — Epic 6: Pagamentos & Monetização (Asaas)

**Status:** Ready (todas decisões fechadas 2026-05-12)
**Owner:** Richard
**Criado:** 2026-05-11

## Motivação

PrintStudio é multi-tenant e cloud-only. Pra virar produto comercial
precisa de billing — Brasil-first (cartão, PIX, boleto) via **Asaas**.

Hoje qualquer usuário cria conta e usa de graça, sem limites. O objetivo
desta epic é entregar a base de monetização: planos, assinatura, controle
de acesso por plano, e o mínimo de painel de cobrança.

**Posicionamento no roadmap:** Phase 3 — Monetization. Depende do Epic 8
(Onboarding) estar funcional pra ter contas pra cobrar.

## Goals

1. Integração funcional com Asaas (sandbox + produção)
2. Modelo de planos (free + pro + business) com limites por tenant
3. Fluxo de upgrade/downgrade na UI (free → pro → business)
4. Webhook Asaas → ativar/desativar/atualizar conta automaticamente
5. Painel admin (owner do tenant) pra ver fatura/assinatura
6. Cobrança **mensal + anual com 20% desconto** desde V1

## Decisões fechadas

- **Gateway:** Asaas (BR-first, PIX nativo, boleto, cartão recorrente)
- **Modelo:** Assinatura por org (não por usuário individual)
- **Estratégia:** Freemium — free forever com limits, paid pra escala
- **Free tier vivo desde signup** (decisão Epic 8) — sem trial,
  sem cartão obrigatório
- **Valores:** Pro **R$ 49/mês** · Business **R$ 199/mês**
- **Periodicidade:** Mensal (default) + **anual com 20% desconto**:
  Pro anual = R$ 470/ano (vs R$ 588/ano se mensal)
  Business anual = R$ 1.910/ano (vs R$ 2.388/ano se mensal)
- **Trial:** Sem trial pago. Free user que upgrade → cobra imediato
- **Reembolso:** Honra **CDC art. 49** (7d arrependimento integral
  pós-contratação). Após 7d, sem reembolso, serviço continua até fim
  do ciclo pago
- **Sub-tenants / white-label:** Skip V1 (todos clientes são tier final)
- **Regime fiscal emissor:** **MEI / Simples Nacional** → emite
  **NFS-e** municipal (não NF-e produto)
- **NF-e:** Adia V1 (story 6.8 fica como **V1.1**). Decidir provider
  (Asaas integrado vs eNotas) quando chegar nessa fase

## Schema additions

```sql
CREATE TYPE subscription_status AS ENUM (
  'active',           -- pagamento em dia
  'past_due',         -- vencido, mas dentro de grace period (7d)
  'cancelled',        -- cancelada manualmente
  'expired',          -- past_due + grace period expirou
  'pending_payment', -- aguardando primeiro pagamento
  'refunded'          -- reembolsado nos 7d CDC
);

CREATE TYPE billing_cycle AS ENUM ('monthly', 'yearly');

CREATE TABLE subscriptions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id uuid NOT NULL UNIQUE REFERENCES organizations(id) ON DELETE CASCADE,
  asaas_customer_id text,
  asaas_subscription_id text UNIQUE,
  plan text NOT NULL,                          -- 'free' | 'pro' | 'business'
  cycle billing_cycle NOT NULL DEFAULT 'monthly',
  status subscription_status NOT NULL DEFAULT 'pending_payment',
  current_period_start timestamp with time zone,
  current_period_end timestamp with time zone,
  cancel_at_period_end boolean DEFAULT false,
  -- Pra CDC 7d (story 6.8)
  first_paid_at timestamp with time zone,      -- início do prazo de 7d
  refund_eligible_until timestamp with time zone, -- first_paid_at + 7d
  created_at timestamp with time zone DEFAULT now() NOT NULL,
  updated_at timestamp with time zone DEFAULT now() NOT NULL
);

CREATE TABLE asaas_webhook_events (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  event_id text NOT NULL UNIQUE,               -- idempotency key from Asaas
  event_type text NOT NULL,
  payload jsonb NOT NULL,
  processed_at timestamp with time zone,
  processing_error text,
  created_at timestamp with time zone DEFAULT now() NOT NULL
);
CREATE INDEX asaas_events_processed_idx ON asaas_webhook_events (processed_at);

-- Dados fiscais da org (capturados no primeiro upgrade pra paid)
ALTER TABLE organizations ADD COLUMN tax_id_type text;       -- 'CPF' | 'CNPJ'
ALTER TABLE organizations ADD COLUMN tax_id text;            -- número formatado
ALTER TABLE organizations ADD COLUMN billing_address jsonb;  -- {street, number, complement, district, city, state, zip}

-- Histórico de cobranças (Story 6.4 + 6.9 future)
CREATE TABLE subscription_invoices (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  subscription_id uuid NOT NULL REFERENCES subscriptions(id) ON DELETE CASCADE,
  asaas_payment_id text UNIQUE,
  amount_cents integer NOT NULL,
  status text NOT NULL,                        -- 'pending' | 'paid' | 'failed' | 'refunded'
  paid_at timestamp with time zone,
  due_date date,
  refunded_at timestamp with time zone,
  refund_reason text,                          -- 'cdc_7d' | 'manual' | 'fraud'

  -- NF-e (V1.1 — story 6.9) — preenchido quando emitida
  nfe_provider text,                           -- 'asaas' | 'enotas' | 'nfe_io'
  nfe_external_id text,
  nfe_number text,
  nfe_pdf_url text,
  nfe_xml_url text,
  nfe_emitted_at timestamp with time zone,
  nfe_error text,

  created_at timestamp with time zone DEFAULT now() NOT NULL
);
CREATE INDEX subscription_invoices_sub_idx ON subscription_invoices (subscription_id, created_at DESC);
```

Credenciais Asaas (API key) seguem mesmo padrão `bambu_credentials` —
criptografadas AES-256-GCM. Pra MVP, ENV global (1 conta Asaas só do
PrintStudio).

## Fluxo upgrade (free → pro mensal)

```
1. User em /settings/billing clica "Fazer upgrade"
2. Mostra comparação de planos (free atual vs pro/business)
   + Toggle [Mensal | Anual -20%]
3. Seleciona Pro mensal → formulário pra capturar:
   - tipo PJ/PF (CNPJ ou CPF)
   - tax_id
   - endereço (CEP + lookup, rua, número, complemento, bairro, cidade, UF)
4. Submit → redirect pra checkout Asaas
   - Cria customer no Asaas se não existe
   - Cria subscription pendente
   - Retorna URL hosted checkout Asaas
5. User paga (cartão/PIX/boleto)
6. Asaas → webhook (event: SUBSCRIPTION_CREATED + PAYMENT_CONFIRMED)
7. Handler:
   - Valida assinatura HMAC do webhook
   - Idempotency via asaas_webhook_events.event_id
   - Update subscriptions.status = 'active'
   - Set first_paid_at = now()
   - Set refund_eligible_until = now() + 7 days
   - Update organizations.plan = 'pro'
   - Invalida cache de limits
8. Redirect user pra /settings/billing com toast de sucesso
9. Banner: "Pro ativo. Você tem 7 dias pra cancelar com reembolso total."
```

## Fluxo reembolso CDC 7d (story 6.8)

```
1. User cancela dentro de 7d desde first_paid_at
   /settings/billing → [Cancelar Pro] → modal:
   "Você está nos primeiros 7d. Reembolso integral garantido pelo CDC.
    Confirmar cancelamento + reembolso?"
2. Submit → backend:
   - Call Asaas API: refund da última cobrança (full amount)
   - Update subscription.status = 'refunded'
   - Update organization.plan = 'free' (downgrade imediato)
   - Set cancel_at_period_end = false (cancelou agora, não esperando fim)
3. UI mostra: "Cancelado + reembolso solicitado. Você verá o crédito em
   até 7 dias úteis."

Caso usuário cancele APÓS 7d (>refund_eligible_until):
- Modal: "Serviço continua até {current_period_end}. Sem reembolso."
- Update cancel_at_period_end = true (mantém Pro até fim do ciclo)
```

## Riscos

- **Asaas API rate limits:** retry/backoff exponencial (jitter)
- **Webhook duplicado / fora de ordem:** idempotência via `event_id`
  unique + processamento idempotente
- **Webhook nunca chega:** poll de fallback diário do status no Asaas
- **LGPD:** dados de cobrança são pessoais, criptografar API key Asaas
- **Free → paid downgrade rápido:** user no Pro com 5 printers cancela
  pra free. Política: bloqueia novos prints mas mantém data 90d,
  depois soft-delete printers excedentes. UX: warning explícito antes
  de confirmar downgrade
- **Reembolso CDC manual fail:** Asaas falha em processar refund →
  fila de retry + notificação Richard via Admin Panel
- **MEI limite anual:** R$ 81k/ano pra MEI. Se virar Simples, regime
  pode mudar pra Lucro Presumido. Acompanhar mensalmente
- **Asaas sandbox vs production env:** garantir ENV separados

## Métricas de sucesso

- Free → Pro conversion: >5% em 30d
- Pro → Business conversion: >10% em 90d
- Churn mensal: <5%
- 0 SQL manual pra alterar plano de tenant
- Webhook do Asaas processado em <2s p95
- 0 duplicações de cobrança (idempotência funcionando)
- % reembolsos CDC 7d: <2% das cobranças (sinal de qualidade do produto)
- Conversion anual: >20% das paid (anual reduz churn)
