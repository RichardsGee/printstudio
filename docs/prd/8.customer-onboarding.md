# PRD — Epic 8: Customer Onboarding (Free Tier Activation)

**Status:** Ready (todas decisões fechadas 2026-05-12)
**Owner:** Richard
**Criado:** 2026-05-12

## Motivação

Epic 7 captura interesse via waitlist. Epic 8 converte o lead em
**usuário ativo** na plataforma. Hoje não existe signup público — só
login pré-cadastrado (NextAuth credentials sem registration endpoint).

Pra escalar PrintStudio sem dependência manual do Richard pra cadastrar
cada novo cliente, precisa de:
- Signup self-service (aberto, não bloqueado por waitlist)
- Onboarding wizard guiado (profile → Bambu → printers)
- Free tier ativo desde o signup (modelo freemium)
- Auto-cadastro das impressoras detectadas (hoje precisa POST manual)

## Goals

1. **Visitor → usuário ativo em <10 minutos** (do signup à primeira
   impressão visível no kiosk)
2. **Zero admin manual** — Richard não roda SQL/API pra ativar conta
3. Free tier funcional desde dia 1 (sem billing necessário pra usar)
4. Onboarding com **drop-off mensurável** em cada etapa pra otimizar
5. **Sinergia com waitlist:** se lead veio via token de convite,
   pre-preenche dados pra reduzir fricção

## Decisões fechadas

- **Auth:** NextAuth credentials (email/senha) — já configurado
- **Signup aberto:** público sem token. Token de convite (Epic 7) é
  **opcional**, só pre-fill se vier. **Não bloqueia** novos cadastros
- **Org auto-creation:** signup cria user + organization + member
  (role=owner) em uma transação atômica
- **Org name default:** "Org de {nome do user}", editável no step
  profile do wizard
- **Free tier limits:** 1 impressora, 7 dias histórico, kiosk +
  dashboard, sem webhooks, sem multi-user (definidos no Epic 6)
- **Skip Bambu Connect:** permitido, com **banner persistente** no app
  ("Sua conta não tem impressora vinculada. Conectar agora?")
- **Liberação waitlist → signup:** manual via Admin Panel (Epic 9).
  Richard clica "Liberar acesso" no lead → sistema gera token de
  convite → Richard envia link manual (WhatsApp/email) com
  `?invite=XYZ`
- **Volume esperado:** 50-200 signups/dia (atenção rate limits Bambu —
  ver Riscos)
- **Email verification:** NÃO em V1 (alinhado com Epic 7 — sem
  provider transactional). Adicionar quando integrar Resend (V2)
- **Password reset:** NÃO automático V1. Página "esqueci senha" mostra
  instrução de contato manual com suporte
- **Termos LGPD:** opt-in obrigatório no signup, checkbox + link pra
  política. Mesmo doc do Epic 7 (compartilhado)
- **Onboarding wizard:** UI em steps, persiste progresso no DB
  (`organizations.onboarding_step`) pra retomar se sair no meio

## Non-Goals (V1)

- Email verification automática (V2)
- Password reset automático (V2)
- SSO / OAuth (Google, Apple) — V2
- Convite de membros adicionais pra org — V2 (free tier é single-user)
- Importar credenciais de slicer externo (PrusaSlicer/Cura) — futuro
- Marketing emails / drip campaigns — V2
- Captcha no signup (rate limit por IP V1)

## Schema additions (story 8.2)

```sql
ALTER TABLE organizations ADD COLUMN onboarding_step text
  DEFAULT 'profile' NOT NULL;
-- valores: 'profile' | 'bambu_connect' | 'add_printers' | 'done' | 'skipped'

ALTER TABLE organizations ADD COLUMN onboarding_completed_at
  timestamp with time zone;

-- Qualificação (sincronizada com waitlist_role do Epic 7)
ALTER TABLE organizations ADD COLUMN role text;       -- 'hobbyist' | 'small_shop' | 'studio' | 'business' | 'other'
ALTER TABLE organizations ADD COLUMN state text;      -- ISO 3166-2:BR (SP, RJ, ...)
ALTER TABLE organizations ADD COLUMN city text;

-- Plano default ao criar org = free (vai pro Epic 6)
ALTER TABLE organizations ADD COLUMN plan text
  DEFAULT 'free' NOT NULL;

-- Vincular signup ao lead de origem (story 8.9)
ALTER TABLE organizations ADD COLUMN waitlist_id uuid
  REFERENCES waitlist(id) ON DELETE SET NULL;

-- Token de convite gerado pelo Admin Panel (Epic 9) quando libera lead
CREATE TABLE invite_tokens (
  token text PRIMARY KEY,                       -- ulid ou random 32 chars
  waitlist_id uuid REFERENCES waitlist(id) ON DELETE CASCADE,
  used_at timestamp with time zone,
  expires_at timestamp with time zone NOT NULL,
  created_at timestamp with time zone DEFAULT now() NOT NULL
);
```

## Fluxo end-to-end

```
1. Visitor entra em guiaprint3d.com (landing Epic 7)
2. (Caminho A) Clica "Solicitar acesso" → entra na waitlist
   → Richard libera depois manualmente → envia link com ?invite=XYZ
3. (Caminho B) Visitor acessa /signup direto (signup aberto)

4. Lead acessa /signup (com ou sem ?invite=XYZ)
   - Email + senha (12+ chars, validation client+server)
   - Nome
   - Checkbox: aceito termos + política
   - [Criar conta]

5. Cria user + org (nome="Org de {name}") + member (owner) na mesma TX
   onboarding_step = 'profile'
   Se ?invite={token} válido → busca waitlist linked, copia
   state/city/role + seta organizations.waitlist_id + marca token usado

6. Redirect /onboarding/profile
   - Input: "Como sua organização se chama?" (org name, pre-fill "Org de {nome}")
   - Dropdown: Estado (BR, 27 UFs)
   - Input: Cidade
   - Dropdown: Qual seu uso? (role enum: hobbyist/small_shop/studio/business/other)
   - Se veio de waitlist: campos já preenchidos, user só confirma/edita
   - [Próximo] → onboarding_step = 'bambu_connect'

7. Redirect /onboarding/bambu-connect
   - Componente reusado de /settings/bambu-connect
   - Após vincular com sucesso → onboarding_step = 'add_printers'
   - OPÇÃO SKIP: [Pular por enquanto]
     → onboarding_step = 'skipped'
     → marca organizations.onboarding_completed_at
     → Redirect /dashboard com banner persistente

8. Redirect /onboarding/add-printers (só se vinculou Bambu)
   - Lista impressoras detectadas da conta Bambu
   - Pra cada uma: checkbox selecionado por default + nome editável
   - Free tier: só permite selecionar 1
   - [Adicionar] → cria printers + onboarding_step = 'done'
   - OPÇÃO SKIP: [Pular] → mesma lógica que skip Bambu

9. Redirect /kiosk (ou /dashboard se skipped)
   - Se completou: mostra impressora recém-adicionada
   - Se skipped: banner amarelo "Sua conta não tem impressora vinculada.
     [Conectar agora →]"
   - Banner welcome em ambos casos: "Bem-vindo! Você está no plano Free."
```

## Free tier limits enforcement (story 8.6)

Centralizar em `lib/plan-limits.ts`:

```ts
export const PLAN_LIMITS = {
  free:     { max_printers: 1,  retention_days: 7,   webhooks: false, max_users: 1 },
  pro:      { max_printers: 5,  retention_days: 30,  webhooks: true,  max_users: 3 },
  business: { max_printers: 999, retention_days: 365, webhooks: true, max_users: 999 },
} as const;

export function canAddPrinter(orgId: string, currentCount: number): Result;
export function canRetainHistory(orgId: string, daysOld: number): boolean;
```

Aplicar em:
- POST `/api/printers` — bloqueia se exceder
- Query history — filtra retention
- Cron de limpeza diária — deleta dados além da retention

## Riscos

- **Conta órfã sem Bambu vinculada:** mitigado pelo banner persistente
  + retomada do onboarding em /settings/bambu-connect
- **Bambu Cloud rate limits com 50-200 signups/dia:** se cada signup
  dispara fetch de devices Bambu, pode bater limite (Bambu rate limit
  exato TBD). Mitigação: cache token por 5min, retry exponencial,
  queue se passar 50 simultâneos. Story 8.4 inclui essa lógica
- **Free tier user adiciona >1 impressora via API direta:** enforcement
  precisa estar no backend, não só UI (já no `lib/plan-limits.ts`)
- **Org name único?** Não vai ser único — múltiplas orgs podem se chamar
  "Estúdio Maker". Usar UUID como identificador interno
- **Senha esquecida sem reset automático:** suporte manual via WhatsApp/
  email do Richard. Limite ~10/semana razoável V1
- **Signup spam aberto:** rate limit por IP (max 5/IP/hora) + honeypot
  igual ao Epic 7. Sem captcha V1

## Métricas de sucesso

- **Tempo médio signup → kiosk com 1 impressora:** <10 minutos
- **Conversion signup → onboarding completo (não skipped):** >60%
- **Conversion signup → ativo no app (qualquer caminho):** >80%
- **Drop-off por step:**
  - signup → profile: <10%
  - profile → bambu_connect: <20%
  - bambu_connect → add_printers: <15%
  - add_printers → done: <10%
- **Tickets de "esqueci senha" manuais:** <5/semana V1
- **% signups que vieram de waitlist (token):** >40% (mede qualificação)
