# PRD — Epic 9: Internal Admin Panel

**Status:** Ready (todas decisões fechadas 2026-05-12)
**Owner:** Richard
**Criado:** 2026-05-12

## Motivação

À medida que PrintStudio escala — waitlist crescendo, signups começando,
subscriptions ativas — Richard precisa de uma visão única e ferramentas
de gestão **direto pela plataforma**, sem SQL manual nem dashboards de
terceiros.

Hoje, qualquer operação admin (mudar plano, marcar lead, ver métricas)
exige acessar o banco direto ou rodar scripts. Não escala.

## Goals

1. Painel `/admin` dentro do app web atual (rota protegida)
2. Visão única de **waitlist + users + orgs + subscriptions + métricas**
3. **Ações operacionais** sem SQL: marcar lead, mudar plano, suspender
   conta, contatar, gerar token de convite (Epic 8)
4. **Filtros + busca + export** pra trabalhar com a base
5. **Métricas em tempo real**: DAU, MAU, conversion, churn, MRR

## Decisões fechadas

- **Localização:** `/admin/*` no mesmo app web (não nova app). Reusa
  auth, design system, deploy
- **Auth:** nova flag `users.is_super_admin` boolean. **Single user V1**
  (só Richard). Multi-admin entra V2 com RBAC granular
- **2FA:** **V2** — V1 protege com senha forte + rate limit login.
  Aceitável enquanto super_admin é só 1 pessoa
- **UI:** mesmo design system Mission Control. Pages no padrão
  `<PageHeader id="ADMIN-XX">`
- **Permission:** server-side check em TODAS as rotas `/admin/*` —
  redirect 404 se não for super_admin (não 403 — não revela existência)
- **No edit destrutivo direto:** delete user/org sempre exige confirmação
  + soft-delete primeiro (não DELETE hard)
- **Audit log:** toda ação admin gera entry em `admin_audit_log` (quem,
  o quê, quando, payload)
- **Impersonation (logar como cliente):** **V2** — não implementar V1.
  Risco LGPD alto. Quando suporte real existir, considera com policy
  forte
- **Backup/restore via admin:** **V2** — backup feito externamente
  (pg_dump cron job ou feature nativa do EasyPanel). Admin não toca
- **Notificações canal interno (lead novo, churn, payment failed):**
  Skip V1. Adiciona V1.1 quando integração Telegram bot do Epic 7
  estiver ativa. Por enquanto Richard checka ativamente via dashboard
  `/admin`
- **Export CSV:** entra como story V1 (P2) — útil pra portabilidade
  LGPD e workflow offline

## Non-Goals (V1)

- Multi-admin RBAC granular (V2 quando equipe crescer)
- 2FA obrigatório super_admin (V2)
- Impersonation / login como user (V2)
- Backup/restore via UI (operação externa)
- Custom dashboards / BI (Metabase / Looker fica futuro)
- Notificações push externas (V1.1)
- Edição de schemas de impressora / cached models (mantém via API/CLI)
- Real-time updates via WebSocket (V1 = pull on demand)

```sql
-- Story 9.9: audit log
CREATE TABLE admin_audit_log (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  admin_user_id uuid NOT NULL REFERENCES users(id),
  action text NOT NULL,                  -- 'waitlist.contact_marked', 'org.plan_changed', etc
  target_type text NOT NULL,             -- 'waitlist' | 'user' | 'org' | 'subscription'
  target_id uuid,
  payload jsonb,                         -- before/after, justificativa, etc
  ip_address inet,
  created_at timestamp with time zone DEFAULT now() NOT NULL
);
CREATE INDEX admin_audit_log_admin_idx ON admin_audit_log (admin_user_id, created_at DESC);
CREATE INDEX admin_audit_log_target_idx ON admin_audit_log (target_type, target_id);
```

## Funcionalidades por seção

### Waitlist (Story 9.3 + 9.4)
- Tabela: nome, email, região, role, status, tags, bambu_count,
  criado_at, last_contact_at
- Filtros: status (new/contacted/engaged/invited/converted/lost), região
  (UF), role (hobbyist/small_shop/studio/business/other), tag,
  range de data
- Busca: nome ou email
- Ações por linha:
  - Marcar status (dropdown inline)
  - Adicionar/remover tag (chip editor)
  - Editar notes (inline textarea)
  - **Gerar link de convite** (Story 9.4) → cria token Epic 8
    `invite_tokens` válido por 30 dias → copia URL pro clipboard:
    `https://app.guiaprint3d.com/signup?invite={token}`
  - Marcar como lost
- Bulk actions: tag/status mass, export
- Métricas no topo: total, novos 7d, conversão signup, status breakdown

### Users/Orgs (Story 9.5 + 9.6)
- Lista de orgs (1 user = 1 org no MVP): nome, plano, status sub,
  printers count, criado_at, última atividade
- Filtros: plano, status sub, atividade (ativos/inativos 30d+)
- Detalhe da org:
  - Aba **Info**: dados básicos, plano, status, datas, tax_id, endereço
  - Aba **Members**: lista users da org
  - Aba **Printers**: impressoras vinculadas (status atual)
  - Aba **Subscription**: histórico cobranças, próxima fatura, NF
  - Aba **Eventos**: log de eventos recentes
  - Aba **Audit**: ações admin sobre essa org
- Ações: mudar plano manual (gera audit entry), suspender, soft-delete

### Subscriptions (Story 9.7)
- Tabela: org, plano, cycle (mensal/anual), status, valor mensal/anual,
  próxima cobrança, total pago, refund eligibility
- Filtros: status (active/past_due/cancelled/refunded), plano, cycle,
  range valor
- Ações: forçar cobrança, marcar como pago manualmente (audit),
  cancelar, refund manual

### Métricas (Story 9.8)
- Cards top:
  - **DAU / WAU / MAU** (Daily/Weekly/Monthly Active Users)
  - **Total signups** + delta 7d/30d
  - **MRR** (Monthly Recurring Revenue, considera anual / 12)
  - **Churn rate** (cancelados últimos 30d / ativos início mês)
  - **Conversion**: waitlist → signup, free → paid em 30d
- Gráficos:
  - Signups por dia (últimos 90d)
  - MRR por mês (últimos 12m)
  - Funil: waitlist → signup → bambu_connected → first_print → paid
  - Distribuição planos (pie chart)
- Filtros: range de data, plano, região

### Audit Log (Story 9.9)
- Log paginado de todas ações admin
- Filtros: admin (V2 multi-admin), action type, target type, range
- Detalhe expansível: payload before/after JSON pretty-printed

### Export (Story 9.10)
- Botão "Exportar CSV" em cada lista (waitlist, users, subscriptions)
- Server-side stream pra evitar memória explodir
- Inclui audit entry quando export executado (compliance)

## Riscos

- **Privilege escalation:** se `is_super_admin` flag for editável via
  endpoint normal, gateway pra abuse. Mitigação: NUNCA expor essa flag
  em PATCH `/api/users/:id`. Edição só via SQL direto/CLI restrito.
  Validar com architect na Story 9.1
- **Performance com waitlist grande:** filtros + busca podem ficar
  lentos com 10k+ rows. Mitigação: indexes definidos no Epic 7
  (status, state, tags GIN) + pagination cursor-based
- **Dados sensíveis no log:** payload pode incluir email, telefone.
  Mitigação: redact em export, LGPD-aware
- **Drift entre admin actions e webhooks:** mudar plano manual no admin
  vs cliente fazendo upgrade real podem conflitar. Mitigação: source of
  truth = Asaas. Admin action força sync depois
- **Acesso compartilhado:** se Richard compartilha senha com alguém,
  conta = root. Mitigação V1: avisar; V2 multi-admin com 2FA
